# 单线程本地 server 与 WebView

页面和原生看护打的是同一个进程里的同一个 server。这个 server 只有一条事件循环时, 谁占着它, 页面就画不出来。

## 事件流

- 读事件的线程只负责把字节读走。不要在这条线程上同步再请求同一个 server。
- 流式增量交给页面渲染。原生侧只在会话收尾 (空闲、完成) 时再查状态，并且放到别的线程，多次收尾并成一次查询。
- 收尾查询晚一点做，先把 server 让给页面画最终内容。完成通知可以晚一秒，页面不能被卡住。
- 短连接、马上结束的成功响应不能当成事件流还活着。网页正文也算成功。只有事件流自己的行才更新存活时间，否则待批轮询会被跳过，横幅出不来。
- 事件总线上的记录编号不是待批请求。对不上能回复的请求时不要发横幅，改去拉待批列表。
- 常驻前台通知会把同应用的提醒收进同一组。组摘要不弹横幅。待批提醒要单独成组，并且渠道要有声音。
- 新安装的包即使渠道已经是高优先级，系统仍可能单独关掉顶部横幅。这项开关默认是关的，要和已经能弹出的那个包对照着打开。
- 本应用正在前台时，系统不把高优先级通知显示成顶部横幅，只留在通知栏。人正在看的页面要自己在顶部画出同一条提醒，按钮走原来的回复。离开页面后再靠系统通知。
- 回复待批请求时用当前服务要求的地址、字段和成功状态码。成功状态不是 200 时，横幅也要撤掉。

## 回前台

- 先让页面自己重连并绘制, 再查 server。立刻并行做全量状态查询, 页面请求会排在后面, 看起来像没有返回数据。
- 判断页面是否已经跟上时, 读 `textContent`。不要用 `innerText`: 它会强制整页布局, 长会话上绘制会停住。
- 探针失败再考虑整页重载。重载是掉线后的补救, 不是对齐的默认动作。
- 只靠实时事件才出现的界面, 回前台用 server 快照对一下页面。快照有、页面没有, 先留一小段时间让还活着的连接自己画出来; 刷新前再向 server 确认一次, 刚处理完的请求不要拿过期快照去刷新。
- 短时间切到后台再回来也要唤醒并对齐正文。已知当前会话目录时只查该目录, 不要为一次对齐扫遍所有工作区。
- 拿来和页面比对的文本必须是页面里真实存在的子串。通知摘要上的省略号不能带进比对。
- 读请求上带的范围参数, 写请求也要带同一份。只在读取时补上的话, 删除和更新会落到默认目录, 目标还在。
- 补这个参数时不要先把原请求重构成新请求。带正文的请求体只能用一次, 重构失败后再发原请求, 正文已经空了, 表现为发不出去。改不了就原样发出去, 不要动本来就能发出去的那种请求。
- 确认框关掉, 不代表操作已经作用到页面上的数据。没发出去或失败时要留下看得见的结果; 成功则让列表或当前位置跟着变。
- 不要在捕获阶段拦住页面自己的确认按钮。拦住之后确认框关不掉, 页面原来的操作也不会执行。
- 触摸点选会关掉自身的菜单项时, 选中发生在按下抬起, 条目随后从页面卸掉。紧接着补发的点击会落到下面的遮罩上, 把刚打开的确认框关掉。丢掉这下补发的点击, 不要拦住真正选中条目的那一下。

## 本机页面仍要求登录

- 原生请求已经带了凭证，页面自己的请求仍被当成另一台未登录的客户端时，用户会看到配对或密码页。
- 用原生侧已经成功的那份凭证换一个一次性的浏览器会话，再让页面打开这个会话地址。不要把密码写进页面脚本。
- 一次性地址只能打开一次。换码和打开要接在同一次加载里。
- 打开这个地址时要让页面自己接收响应里的 cookie。把响应读进原生再交回页面，cookie 不会进页面。

## 探活

- 页面要等探活成功才加载。探活打到已经不存在的路径时，成功等不到，用户看到的仍是启动遮罩或上一版界面。
- 把「路径不存在」和「进程挂死」当成同一件事去重启时，旧进程还占着端口，新进程起不来，最后两边都没了。
- 换服务版本时，先确认探活用的是这个版本仍然会返回成功的地址，再让看护根据失败去重启。
- 安装包里的服务程序按这次构建指定的版本下载。目录里已经有旧产物时，不能只因为版本文件存在就跳过。跳过条件要比对记录的版本和这次要打的版本，不一致就重新取程序。
- 只换程序时改程序文件和它的指纹。基础环境指纹保持不变，用户在环境里另外装的工具才不会被整包重装清掉。

## 挂在页面上的设置

- 设置区块要挂在当前页面真实存在的页签上。页签改名之后，还按旧名字找，区块就不会出现。
- 新旧名字都认，优先挂到和这件事对应的那一页。

## 窄屏

- 先看页面自己的断点已经收起了什么。已经收起的侧栏、分栏不要再用注入样式藏一次, 也不要藏掉用来打开抽屉或回到会话的那个按钮。
- 同一行里只有可变文案可以收缩并省略。固定操作保持可点尺寸, 次要控件放进可展开的一层, 不要和主操作抢位置。
- 响应式页面不要开整页缩放。缩放后的宽度和窄屏断点不一致, 布局会乱。
- 虚拟列表的行高是量出来的。不要用样式把其中一行压扁, 滚动位置会跳。折叠交给页面自己的展开状态。
